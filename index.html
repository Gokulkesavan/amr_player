Parsing notes
• Ethernet / Linux SLL / raw IP link layers, IPv4 + IPv6 with extension headers.
• ESP is decoded when the payload is not encrypted (ealg=null, RFC 2410) — exactly what IMS sec-agree uses when the operator configures the null cipher. The ICV length (SHA-1-96 / SHA-256-128) is auto-detected.
• SIP is reassembled from TCP streams by sequence number; SDP rtpmap/fmtp drive the RTP payload interpretation.
• Audio duration comes from RTP timestamps, not arrival time — that is what fixes the “wrong duration / crackling” you get from naive RTP extraction.

How the duration is computed

Each RTP packet carries a 32-bit timestamp expressed in samples of the codec clock (16 000 Hz for AMR-WB, 8 000 Hz for AMR-NB). The gap between two consecutive timestamps is the exact amount of audio that should sit between them — including any packets that were lost in transit. Naive extractors concatenate the payloads they happen to receive and therefore shorten the file and make the codec state machine produce clicks.

This tool walks the RTP timestamps, inserts NO_DATA frames (FT = 15) for every missing 20 ms slot, and writes a proper #!AMR-WB / #!AMR storage file. That file plays with the correct length in VLC, ffmpeg, Audacity, etc.
